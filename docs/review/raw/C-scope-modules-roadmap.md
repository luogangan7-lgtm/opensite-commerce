## 分析与修复

- C01 根因：买方模型未定义。修复：Identity 管认证，顾客域管资料/地址，B2B 管公司、成员及买方角色。验收：顾客不能进后台，公司间订单隔离，成员退出即时失权。
- C02 根因：缺唯一所有者。修复：Pricing 管价格，Cart 管购物篮，Orders 管订单快照；checkout 应用层编排。payments→orders 单向 GetPayable 可行，禁双向互调。验收：三表归属一致、依赖无环；重复提交、报价失效、失败及迟到支付 E2E。
- C03 根因：基础能力散落业务 PR。修复：新增共享基础 PR，先于订单、审批及支付，明确队列与 outbox 原子提交。验收：提交/投递间宕机、重复及乱序注错后恢复，无丢事件或重复副作用。
- C04 根因：单币账本、FX、卖家结算混成 PR16。修复：单币账本先于账期应收及内部记账；纯 B2C 不必先造 FX。卖家契约先于结算。验收：收款、退款、应收冲销可对账；借贷平衡、每笔来源唯一。
- C05 根因：纯引擎与购买集成依赖未分层。修复：PR12 需地址/税分类/免税/价格契约；按仓库发货地计税才依赖 PR09。PR14 需共享基础/payable；购买验收另需库存/运费/税额/B2B策略/checkout。验收：换仓/地址/折扣后重报价，未审批或金额失效不能付款。
- C06 根因：不可取的 schema 被当成运行基线。修复：补 Catalog/CMS 契约及 Astro 骨架，再做 PR06；PR18 补身份/CMS/registry/发布依赖；PR19 需草稿权限/同步服务，可脱离 PR18。验收：干净检出可预览/发布，越权编辑失败。
- C07 根因：退款/物流/发票表代替业务闭环。修复：补履约行/拣货/部分发货/取消；RMA 授权/验货/回库关联退款；票据签发/冲销/地区税票适配。验收：不超发、不超退，不重复回库/退款，票据可对账。
- C08 根因：异步底座代替运营产品能力。修复：补通知模板/重试、审计查询、对外 webhook 签名/重放、导入预检/导出；定义 GDPR 等适用市场的数据权利、匿名化/留存/恢复策略。验收：失败可追踪，重放安全，跨租户拒绝，恢复不复活已删除个人数据。
- C09 根因：adjustments、sites、i18n 目录不等于完整能力。修复：促销内聚 Pricing；Sites/Publishing 负责域名、语言路由、商品范围、canonical/hreflang/sitemap。验收：优惠额度并发及税额正确，两站两语言无串站。
- C10 根因：能力路线替代发布路线。修复：PR04 拆四域；PR10 拆公司/账期；PR16 拆账本/FX/结算；PR18 拆 SDK/代码沙箱；PR20 拆子 PR。验收：各 PR 独立验收/回滚。

## MVP 切线

单站/单语言/单币/单仓，模型保留 warehouse_id；B2C 顾客/访客购买，B2B 公司/报价/单层审批/预付；Stripe、区域税规则、手工履约、LocalFS，含基本售后/票据/通知/审计/数据权利。首发验收：两条购买路径及退款/取消、宕机恢复、隔离、备份恢复在同一 SHA 全绿。

V1.x 延期：账期授信、多仓调拨、复杂促销、多站多语言、Adyen、FX/Marketplace、插件沙箱、Yjs、可选基础设施；存储迁移工具可后移。

## 系统性问题

缺“用户路径→模块/表所有者→契约→PR→上线验收”追踪链。图、目录、能力表粒度不同可以成立，但必须共用归属与依赖依据；发布单位应是购买、履约、售后闭环。
