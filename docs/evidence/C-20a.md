# C-20a fulfillment / returns acceptance

This card preserves migration 020: payment commits all reserved stock. Shipment
allocates committed order quantities without touching inventory. Paid unshipped
cancellation records its quantity/reason, restores stock through a controlled
adjustment and refunds through the same durable return protocol. Keeping paid
reservations alive would require expiry-sweep changes and conflict with checkout.

## Reproducible invariants

| Boundary | Automated evidence |
| --- | --- |
| No over-shipment, over-return or canceled-unit reship | `tests/db_fulfillment_returns.sql`; advisory-lock races 70–79 |
| Parent serialization includes repeatable-read clients | Physical order-parent write; race 79 |
| Tenant isolation, immutable creation/receipt replay | SQL tests, strict-handler tables, actual PG integration |
| Restock once, illegal state changes rejected | SQL negative tests and order-version fencing |
| Frozen net/tax/shipping allocation conserves paid total | SQL allocation edge cases and Go PG integration |
| Provider success followed by DB failure can recover | Permanent prepared intent and Fake Payment Port; one journal |
| Only an exact balanced refund journal can complete | SQL forged-journal negative test |
| Actor and operation isolate a wire key | Actual PG command test and fulfillment HTTP integration |
| In-progress is 409; changed reuse is 422 | C-04 PG test and strict-handler tests |
| Exact HTTP response and domain commit are atomic | C-04 completion/store-failure tests and refund callback |

The actual PG business scenario pays four units (460 minor units), ships two,
cancels/restocks two and refunds 230 with balanced income/tax/shipping/cash lines.
Returning the shipped remainder restores the original stock and total refund.
The HTTP variant additionally proves exact replay and different-actor isolation.

## Red → green receipts

Tests were written before the new migration. The pre-migration test failed;
the forward migration made it pass. Six SQL fault probes then independently
removed quantity bounds, original-response stability, once-only restock, exact
journal proof and physical-parent fencing; each failed its assertion, and the
restored migration passed. Runtime refund-completion privileges were separately
absent/red before the narrow `refundReturn` policy was added/green.

Go probes removed precise command-key conflict classification and the final
refund-completion callback. Actual PG tests failed for wrong-key behavior and
unpropagated finalization failure, then passed after restoration. Capture-total
and provider-reference guards also have independent failing probes.

C-04 probes omitted actor identity from the domain key and ignored durable
completion failure. Actual PG tests respectively failed with `different actor
shared receipt` and an erroneous 201 on store failure, then passed restored.
HTTP probes removed shared completion and bootstrap actor forwarding; both
failed focused tests and restored tests passed. Contract deletion also failed
the new implemented-operation reconciliation gate.

## Composition and limits

This card adds a trusted-actor projection only, in its own commit; no session or
API-key authentication is implemented. C-02b will supply the real actor source.
Without authenticated admission, production writes fail 401. Trusted captured
payment/account/Payment Port bindings must be injected; missing composition
fails closed and no production Fake is created. Response storage must be durable
and shared. A failed/interrupted admitted request remains 409 until its default
two-minute claim lease permits recovery. Provider idempotency remains permanent.

Real payment providers, authentication deployment, carrier APIs, return labels,
exchanges and multi-warehouse routing are **NOT_RUN / outside this card**. There
is no production acceptance claim. Unpaid cancellation remains Orders-owned.
Rollback means stopping the new routes and applying a reviewed compensating
forward migration; existing migration history must not be rewritten.
