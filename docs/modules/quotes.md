# Quotes contract

Quotes owns `inquiries`, `quotes`, `quote_lines` and `quote_approvals` writes through generated SQL queries and narrow database commands. It emits `quotes.created` and lifecycle events through the shared transactional outbox. It does not create orders, reserve stock, take payment or post a ledger entry.

`contract/types.go` defines the public DTOs and stable errors. `Module` exposes `SubmitInquiry`, `Create`, `Get`, `Transition` and `GetAcceptedQuote` on caller-owned tenant transactions. `Application` exposes context-only HTTP commands through `TenantRunner`; it owns no pool. The runner always receives a tenant from a trusted identity stamp. HTTP must authorize employee scopes before attaching a staff stamp. Buyer authentication and host/site inquiry resolution default to denial when no trusted stamp exists. Database commands independently verify current active staff/company members.

Create requires `If-Match: *` and a nonempty `Idempotency-Key`. Later writes require the exact strong ETag `"quote-<uuid>-v<version>"`. Receipt hashes include tenant, actor kind/ID/company, operation, target, precondition and payload. Receipts use shared 011 claims in the same transaction as all domain writes; stored JSON responses replay only after current membership and company access are rechecked. An old successful receipt remains replayable after expiry for an authorized actor; replay is history, and cannot make an expired quote usable.

Amounts are signed int64 minor units with explicit uppercase currency. Quantity is a positive integer. Seller-negotiated unit prices need not match a public price list. Quotes loads tax/shipping rules inside the tenant transaction, calls the existing pure calculators, and freezes line net/tax/gross, selected rate snapshots, shipping charge, totals, destination, calculation time and calculator identity. Line `line_total` is net; quote `subtotal + tax + shipping = total`. Caller input and later rule changes cannot mutate the persisted snapshot.

State transitions are draft → sent → accepted_pending_approval → approved/rejected. Only staff sends, withdraws or expires quotes. Only active company members accept; an active approver/admin distinct from the accepting member decides. Sent/pending quotes may become withdrawn/expired. Expiry uses a strict future boundary for acceptance and approval. Buyers cannot read or act on drafts (indistinguishable from a missing quote); staff see every state. `GetAcceptedQuote` returns only approved quotes whose expiry is still in the future by the database clock (`clock_timestamp()`), after the same access checks; the API host clock never decides validity. Snapshot changes require a new quote. A quote holds at most 100 lines; snapshots and replay receipts are bounded by `MaxStoredJSONBytes` (derived from 100 lines × 8 KiB plus 64 KiB) under a 1 MiB database hard cap. Public inquiry receipts always report `received`; the stored CMS workflow status stays internal.

Acceptance gate: public-port exact-calculator/state/identity tests, injected self-approval guard red → green, PostgreSQL migrated role/CAS/tenant/company/idempotency/snapshot tests under the pgxadapter runner, and the root's frozen-SHA full gates. Focused receipts live in `.work/c17-service`; PostgreSQL tests require DATABASE_URL and never silently skip. No E4 or runtime identity production validation is claimed by focused Go tests.
