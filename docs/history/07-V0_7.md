# OpenSite Commerce V0.7 — ORM 决策与工程实施

## 一、是否需要 ORM？结论：核心系统不需要传统 ORM

经过重新评估，我建议正式采用：

**Go + pgx/v5 + sqlc + PostgreSQL 18，不引入 GORM 或 Bun ORM。**

这不是因为 ORM 性能一定差，而是因为你的独立站平台有几个特殊要求：

- 商品数量可能达到数万 SPU、数十万 SKU。
- 同一套系统支持 B2B、B2C、多网站与多行业。
- 商品价格、库存和订单需要明确的事务控制。
- 企业数据需要使用 PostgreSQL RLS 隔离。
- Agent 可以进行大批量创建、修改和发布。
- 需要稳定的 SQL 迁移、版本管理与可追溯审计。

这些要求更适合由明确的 SQL 和业务领域服务控制。

### 1.1 四种方案对比

| 方案 | 开发效率 | SQL 可控性 | 大批量商品处理 | 推荐 |
|---|---|---|---|---|
| GORM | 普通 CRUD 较快 | 支持原生 SQL，但 ORM 抽象较多 | 需要专门优化 | 不作为核心 |
| Uptrace Bun ORM | CRUD 与复杂关系查询较方便 | SQL-first，控制力较好 | 支持批量操作 | 保留备选 |
| pgx | 需要编写 SQL | 完整控制 | 支持 PostgreSQL COPY | 采用 |
| pgx + sqlc | SQL 显式，自动生成类型化 Go 代码 | 完整控制 | 可结合 COPY 和暂存表 | **首选** |

GORM 和 Bun ORM 都是成熟方案。GORM 支持关联、事务、复合主键和批量插入；Uptrace Bun 支持复杂关系、事务及 SQL-first 查询。它们并非无法实现这个项目。

关键区别在于维护方式。

传统 ORM 倾向于让 Go 模型参与定义数据库关系和查询行为。

而我建议 OpenSite Commerce 坚持：

> **PostgreSQL Schema 是数据结构的权威；SQL 是数据访问契约；Go 领域服务负责业务规则；OpenAPI 负责对外接口。**

### 1.2 sqlc 能减少多少手写代码？

例如，开发者只需要编写：

```sql
-- name: GetProduct :one
SELECT id, product_code, status
FROM app.products
WHERE tenant_id = $1
  AND id = $2;
```

`sqlc generate` 就可以生成对应的 Go 查询方法、参数结构和结果类型。

这意味着我们仍然能够获得类似 ORM 的部分开发便利，但不用将复杂查询隐藏在 ORM 关联加载规则之下。

sqlc 官方明确支持生成 `pgx/v5` 代码。

### 1.3 大批量商品怎么办？

例如导入 300,000 个服装 SKU。

不应通过 ORM 逐条调用 `Create()`，也不应该简单循环执行 300,000 次 INSERT。

推荐：

**文件解析 → 暂存表 → PostgreSQL COPY → 数据验证 → 分批 UPSERT → 审计结果。**

pgx 原生提供 `CopyFrom`，能够使用 PostgreSQL COPY 协议批量写入数据。

实际导入还需要处理唯一性冲突、重试、分批事务和失败回执。COPY 是数据传输手段，不会自动解决这些业务问题。

### 1.4 RLS 与事务如何管理？

采用统一的事务执行器：

```text
API 请求
   ↓
认证与授权
   ↓
开始 PostgreSQL 事务
   ↓
设置可信 Tenant Context
   ↓
调用 sqlc 查询或领域命令
   ↓
写入审计与后台任务
   ↓
提交 / 回滚
```

不允许部分查询绕过这个入口，直接使用没有租户上下文的数据库连接。

这样能够减少连接池复用造成的租户上下文错误。

### 1.5 正式架构决定：ADR-070

**核心数据访问采用 pgx/v5 + sqlc。**

同时确定：

1. 不使用 GORM AutoMigrate 管理正式数据库。
2. 不引入 Uptrace Bun ORM 作为默认依赖。
3. 所有数据库结构变更使用 forward-only SQL 迁移。
4. 核心查询由 sqlc 生成类型化 Go 代码。
5. 特殊批量导入使用 pgx COPY 和显式 SQL。
6. 动态商品筛选采用受控查询构造，不允许拼接用户提供的 SQL。
7. 所有写操作经过领域服务、事务和授权检查。

**另外，Bun JavaScript Runtime 仍保留为前端开发工具链。** 不采用 Go Bun ORM，并不影响使用 Bun 安装、构建和测试 React、Astro 项目。

这是我建议正式冻结的数据库访问方案。
